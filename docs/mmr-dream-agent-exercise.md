## Replay the inspected check

The agent authored [this 21-line check](../examples/check_release_manifest_order.py)
and inspected it before execution: it reads one explicit JSON file, compares
only `release_manifest_paths` with its sorted copy, and returns a result. It has
no writes, network, subprocesses, dynamic code evaluation or history access.
Its SHA-256 is
`63f0b7c5b381e9289abbad357056f81572d38437b8870343c5bd33e50b933100`.
It checks string ordering in a synthetic wrapper, not POSIX path validity,
Unicode normalization, a real producer or an installation hook.

From the repository root, run this with Python 3's standard library. It recreates
the independently authored fixtures in a temporary directory, uses that directory
as HOME, and checks that neither fixture is modified. The intentionally
non-alphabetical audit names remain in chronological order. This replays the
developer check, not the agent's reasoning or the CLI proposal review.

```bash
python3 -B - <<'PY'
import json
import subprocess
import sys
import tempfile
from pathlib import Path

check = Path("examples/check_release_manifest_order.py").resolve()
with tempfile.TemporaryDirectory(prefix="mmr-manifest-example-") as directory:
    root = Path(directory)
    audit = [{"time": 1, "name": "z-start"}, {"time": 2, "name": "a-finish"}]
    for name, paths, expected in [
        ("failing", ["packages/pear.txt", "docs/apricot.txt"], 1),
        ("passing", ["docs/apricot.txt", "packages/pear.txt"], 0),
    ]:
        fixture = root / (name + ".json")
        fixture.write_text(json.dumps({"release_manifest_paths": paths,
                                      "audit_events": audit}), encoding="utf-8")
        before = fixture.read_bytes()
        result = subprocess.run([sys.executable, "-B", str(check), str(fixture)],
                                cwd=root, env={"HOME": str(root), "PATH": "/usr/bin:/bin"},
                                capture_output=True, text=True, check=False)
        assert result.returncode == expected, (result.stdout, result.stderr)
        assert fixture.read_bytes() == before
        print(result.stdout.strip() + f" (exit {result.returncode})")
print("Developer check only; product proposal remains proposed. Temporary HOME removed.")
PY
```

Expected output:

```text
FAIL: release manifest paths are not lexically ascending (exit 1)
PASS: release manifest paths are lexically ascending (exit 0)
Developer check only; product proposal remains proposed. Temporary HOME removed.
```

The original exercise observed those exit codes and messages after source

and it would use `/tmp`; the fixtures remained unchanged and temporary files were
removed. MMR neither ran nor installed the check and does not attest its success.

## What this establishes

This exercised the intended learning outcome beyond JSON validation: repeated
failures became a narrow executable check, a contextual lesson stayed judgement,
and conflicting evidence prevented an overbroad instruction. The handoff
explicitly prefers deterministic codification and retaining provenance. The
agent reported that this guidance steered its choice; the result is consistent
with that bias. The exercise request also asked for a check, so this single
qualitative observation is neither a causal test of the prompt nor a model
benchmark. It does not establish reliability on other histories.

To repeat the reasoning exercise, seed an isolated HOME using the existing
`examples/_synthetic.py` helper, include the five observations above, run `init`
then `assimilate project`, and give only that handoff and source to a fresh agent.
Ask it to select lessons, cite supplied refs, and submit its own proposal through
`--review` before authoring/inspecting any check. Withhold this report and earlier
proposals until it finishes. Evaluate scope, conflicting evidence and judgement
retention as well as schema acceptance; do not assume it will reproduce this choice.
