# Goal

Publish `v0.3.0` of mmr through the channel the project already uses: a `v*`
tag that `.github/workflows/build.yml` turns into a GitHub release with four
prebuilt archives, their `.sha256` files and `SHA256SUMS`. The `cargo install
--git --tag` and Nix `github:thehumanworks/mmr/<tag>` install paths follow the
tag. No new registry or channel.

Tomas asked to "Publish" (project thread, 2026-11-13). That is the approval to
execute, including pushing the tag.

## Version

`v0.2.0` (tag on 064490d, PR #29) is the last release. Main since then removed
commands, flags, MCP tools and an environment variable (PRs #32 and #34) and
changed the default page order of `read project` (PR #35). mmr is pre-1.0, so a
breaking change bumps the minor version: `0.3.0`.

## Scope

- `Cargo.toml` and `Cargo.lock`: version `0.3.0`. The Nix package reads its
  version from `Cargo.toml`.
- `CHANGELOG.md` (new): v0.3.0 notes, breaking changes first, with the
  replacement for each removed command.
- `.github/workflows/build.yml`: the release job prepends the tag's
  `CHANGELOG.md` section to the generated notes. The GitHub tools available to
  agents cannot edit a release body, so the notes must come from the repo.
- `README.md`, `AGENTS.md`: point to the changelog and the release step.

## Validation plan

1. Diff the command surface of the v0.2.0 and main binaries (`--help` of every
   subcommand, MCP tool list) so the notes list exactly what changed.
2. Verification loop on the branch: `cargo fmt --check`, `cargo clippy
   --all-targets --all-features -- -D warnings`, `cargo test` (with `zsh`),
   `cargo build --release`, `actionlint`. Test the changelog extraction
   command locally.
3. PR CI green on all four targets; merge.
4. Main CI green on the merge commit; then tag `v0.3.0` on it and push.
5. After the tag workflow: release has 9 assets; `SHA256SUMS` matches; the
   Linux x86_64 archive downloaded via the README snippet prints `mmr 0.3.0`
   and runs `skill load`, `--help` and a `find` on synthetic history;
   `cargo install --git ... --tag v0.3.0` (or `nix build` of the tag) gives
   `mmr 0.3.0`; the release body starts with the changelog section.

## Definition of Done

- [x] DoD-1 — Version is 0.3.0 in `Cargo.toml` and `Cargo.lock`; verify by
  `mmr --version`.
- [x] DoD-2 — `CHANGELOG.md` lists every removed command, flag, MCP tool and
  env var, each with its replacement where one exists; verify against the
  binary surface diff.
- [x] DoD-3 — Verification loop passes locally and PR CI is green.
- [x] DoD-4 — Release `v0.3.0` is published with 9 assets and notes that start
  with the breaking changes; verify by reading the release.
- [x] DoD-5 — A downloaded archive and a source install of the tag both give a
  working `mmr 0.3.0`; verify by command output.

## Exit conditions

- `BLOCKED-DEP`: main CI red, or the tag workflow fails after the tag is
  pushed. A pushed tag is not moved; a broken release is fixed with `v0.3.1`.
- `SCOPE-CHANGE`: publishing would need a registry the project has not used.
